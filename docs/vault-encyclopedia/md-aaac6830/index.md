# 限界上下文

### 划分原则

1. **语言一致性原则**：同一个词在不同上下文中含义不同。"订单"在销售上下文中意味着客户购买意向，在物流上下文中意味着待发货包裹，在财务上下文中意味着应收账款。当一个概念在不同团队中产生歧义时，就是划分上下文的信号。
2. **自治性原则**：每个限界上下文应由一个团队独立拥有，拥有自己的数据存储、业务逻辑和技术栈选择。上下文之间通过明确的契约（API、消息、事件）通信，而非共享数据库。
3. **内聚性原则**：同一上下文内的概念高度内聚，变更频率一致。如果两个模块总是同时变化，它们可能属于同一上下文；如果变化互不相关，应考虑拆分。
4. **业务能力映射**：限界上下文通常映射到企业的业务能力单元——"库存管理"、"客户关系"、"订单履约"各自成界。
