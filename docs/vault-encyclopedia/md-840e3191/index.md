# 通用语言

## 📌 核心定义

> 通用语言（Ubiquitous Language）是领域驱动设计（DDD）中开发者与业务专家共同建立、共同使用的统一术语体系——它不是技术行话，也不是业务黑话，而是两个群体在协作中自然形成的共享语言，贯穿需求讨论、代码实现和文档表达。

## 🎯 关键要点

- 语言驱动模型：语言中的名词映射到实体和值对象，动词映射到服务和命令，规则映射到领域逻辑。
- 模型约束语言：模型的结构反过来规范语言的使用——如果一个概念无法在模型中找到对应位置，它要么不属于当前上下文，要么模型需要重构。

## 📖 详细说明

### 概念解释
通用语言（Ubiquitous Language）是领域驱动设计（DDD）中开发者与业务专家共同建立、共同使用的统一术语体系——它不是技术行话，也不是业务黑话，而是两个群体在协作中自然形成的共享语言，贯穿需求讨论、代码实现和文档表达。
### 如何建立通用语言

1. **从领域专家的语言出发**：开发者不应将技术概念强加于业务方。当业务专家说"下单"，代码中就应该是 `placeOrder()`，而非 `createRecordInOrderTable()`。
2. **持续对话与提炼**：通用语言不是一次性产出的词汇表，而是在反复的需求讨论、模型重构中逐步精炼的。每次发现歧义，都是改进语言的机会。
3. **统一到代码中**：通用语言必须体现在代码的类名、方法名、变量名中。如果业务专家看不懂你的代码结构，说明语言还没有真正统一。
4. **用文档固化**：维护一个团队共享的术语表（Glossary），记录每个核心概念的精确定义、边界条件和典型用法。

### 避免翻译层

传统开发中最常见的效率杀手是"翻译层"的存在：

- 业务专家说"客户"，开发理解为 `User`，数据库里叫 `t_usr_info`。
