# PastSpec 驱动开发（SDD）

## 📌 核心定义

> 把规格当作 PR 的一部分，让队友和 Agent 都能对照同一份文档。

## 🎯 关键要点

- 把规格当作 PR 的一部分，让队友和 Agent 都能对照同一份文档。
- Agent 出错往往是需求理解偏差。解决办法是把规格当作 PR 的一部分，让队友和 Agent 都能对照同一份文档。
- **产品规格（PRODUCT.md）**：做什么，用户视角、用户故事、可验证的产品不变量
- **技术规格（TECH.md）**：怎么做，架构、代码位置、实现策略
- 都放在 `specs/<issue>/` 目录，随实现 PR 一起提交、一起 Review。
- 从用户行为出发，写用户故事和详细的不变量（invariants）——即「无论什么情况都必须成立」的规则。可附 Figma、截图等。这些不变量后续可被代码检查，甚至用 computer use 验证。
- 在同一目录生成 TECH.md，说明架构思路、改哪些文件、实现时要注意什么。这是给 Agent 的「施工图纸」。
- 理论上任何 Agent、包括推理能力较弱的模型，只要有清晰规格，实现质量都会更稳定。
