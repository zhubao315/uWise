# 驾驭工程

## 📌 核心定义

> **定义**：区别于Prompt Engineering和上下文工程，驾驭工程解决的是"AI在什么环境里工作"的问题——它关注的不是单次对话的输入输出，而是AI稳定运行所需的整个环境体系。

## 🎯 关键要点

- 适时：在正确的时机提供正确的背景
- 适量：既不过少导致幻觉，也不过多导致噪音
- 适质：信息准确、结构清晰、来源可信
- 知识团队：负责知识资产的采集、结构化、更新
- 平台团队：负责上下文供给管道和Skill框架

## 📖 详细说明

### 概念解释
**定义**：区别于Prompt Engineering和上下文工程，驾驭工程解决的是"AI在什么环境里工作"的问题——它关注的不是单次对话的输入输出，而是AI稳定运行所需的整个环境体系。
### 为什么需要驾驭工程

当AI从"偶尔使用的工具"变成"日常工作伙伴"，单次交互的优化远远不够。AI需要一个稳定的、可维护的、持续演进的工作环境，才能持续产出高质量结果。这就像人类员工需要办公室、工具、流程手册、知识库一样——AI也需要它的"工作环境"。

### 驾驭工程的四大支柱

#### 1. 知识资产（Knowledge Assets）

组织积累的结构化和非结构化知识，包括：
- 产品文档、技术规范、业务规则
- 历史决策记录、复盘文档
- 行业知识库、最佳实践库
- 代码库、配置模板、架构图

知识资产的质量直接决定AI的输出质量。垃圾进、垃圾出——这个规律在AI时代被放大了十倍。

#### 2. 上下文供给（Context Supply）

为AI提供适时、适量、适质的上下文信息：
- **适时**：在正确的时机提供正确的背景
- **适量**：既不过少导致幻觉，也不过多导致噪音
- **适质**：信息准确、结构清晰、来源可信

上下文供给不是一次性的事，而是一个持续的、动态的信息管道。

#### 3. Skill维护（Skill Maintenance）

AI的能力边界需要持续维护和扩展：
- 定义AI可以执行的操作范围
- 维护工具调用的权限和规范
- 更新AI的行为模式和响应策略
- 测试和验证AI的新能力
