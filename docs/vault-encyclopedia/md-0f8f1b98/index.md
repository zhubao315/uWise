# 后端架构设计

> 构建可扩展、可维护、高性能后端系统的架构方法论。

## 常见架构模式

| 模式 | 特点 | 适合场景 |
|------|------|---------|
| **单体** | 简单直接，部署方便 | 早期/MVP |
| **微服务** | 服务拆分，独立部署 | 中大型团队 |
| **Serverless** | 无服务器，按调用计费 | 事件驱动/突发流量 |
| **事件驱动** | 解耦异步，高吞吐 | 实时数据处理 |

## 设计原则

1. **SOLID 原则**：单一职责/开闭/里氏/接口隔离/依赖反转
2. **DDD 分层**：领域层→应用层→基础设施层
3. **CQRS**：读写分离，优化各自路径
4. **优雅降级**：部分故障不影响核心功能

## 关键考量

| 维度 | 考量点 |
|------|--------|
| **性能** | 缓存策略/数据库优化/异步处理 |
| **可用性** | 多副本/故障转移/限流熔断 |
| **安全** | 认证授权/数据加密/SQL注入防护 |
| **可观测** | 日志/追踪/指标/告警 |
