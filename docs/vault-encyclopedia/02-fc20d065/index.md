# 02 词条标准化规范

## 🚫 准入铁律（2026-09-23 · O-105/O-107）

> 词条**不能是书名/概念名镜像**，必须是**从源中提炼的可调用智慧**。范例：[可消亡部件·架构演进·分布式取舍——《凤凰架构》三条智慧](../md-5ead4006/)（source→真本）。

| 禁止 | 允许/要求 |
|------|-----------|
| `《书名》-作者.md` 直接进 uWise | 书名/概念正本留 `07-SOURCES` / `01-BRAIN` |
| 占位句「是一个重要的知识概念…」（expand_placeholders 模板） | 提炼 1 条主题智慧 + 3 条分论点 |
| 仅复述定义，无操作面 | 必含 `## 调用示例` + `## 边界约束` |
| `source` 空或指向 uWise 自身 | `source` 指向真本 wikilink（07-SOURCES / 01-BRAIN） |

**提取生成步骤（读书/概念 → 词条）**：
1. **先检索**（G3）：01-BRAIN/07-SOURCES 已有则合并，禁重复新建。
2. **选源**：读 `source` 真本，禁对空源套模板。
3. **提炼智慧**：1 条主题（`## 核心定义`）+ 3 条分论点；每条含 **原文核心 / 通俗理解 / 产品启示 / 面试可提问**（按需裁剪）。
4. **补操作面**：`## 调用示例`（trigger/场景 ×3）+ `## 边界约束`（适用/不适用/失效条件）。
5. **回链**：`source` + 正文 ≥1 个真本 wikilink + 概念稿/索引入链；入 `01-BRAIN` 新笔记则出链 ≥2（G1）。
6. **命名**：智慧主题短语（禁纯书名）；FM 必填 `title`/`created`/`tags`。

## 🎯 设计原则

### Harness Engineering可读性原则

2. **可扫描性**：结构清晰，便于快速浏览
3. **可检索性**：包含丰富的元数据
4. **可关联性**：明确的知识关联

### Agent可读性要求

2. **明确语义**：避免歧义表述

## 🏷️ 标签规范

## 📁 文件命名规范

### 命名规则
1. **使用中文**：便于阅读
2. **简洁明确**：准确反映内容
3. **避免特殊字符**：不使用 `/ \ : * ? " < > |`
4. **统一格式**：保持一致性

### 命名示例

## 🎯 最佳实践

### 编写建议
1. **先定义后展开**：核心定义放在最前
2. **由浅入深**：从基础概念到高级应用
3. **多举例子**：用案例说明抽象概念
4. **建立关联**：主动链接相关知识
5. **保持更新**：定期回顾和完善

### 常见错误
1. ❌ 定义过于复杂
2. ❌ 缺少实际案例
3. ❌ 关联知识不足
4. ❌ 标签使用混乱
5. ❌ 格式不一致
