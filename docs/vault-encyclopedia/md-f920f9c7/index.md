# 组织机器化管理

## 📌 核心定义

> 组织机器化管理是瑞·达利欧《原则》工作原则的核心框架：把组织视为一台机器——人是齿轮、流程是结构、问题是故障。管理者的两项职责是**设计机器**与**改进机器**，而非只是操作机器。出了问题不怪人，怪设计。

## 🎯 关键要点

- **人是机器中的齿轮**：人岗匹配=齿轮匹配，齿轮大小形状必须与岗位匹配
- **问题是机器故障**：不怪人，怪设计——"是系统让你犯了错，不是你本身有问题"
- **管理者两项职责**：设计机器（流程/标准/文化）+ 改进机器（发现→诊断→改进）
- **病态机器**：忙于"操作"（救火）而从不"改进"（优化系统）→ 同样故障反复出现
- **决策层级**：原则层（核心制定）→ 战术层（部门自主）→ 执行层（一线自主）；**原则先行，决策后置**
- **问题日志**：全员可提问题→解决→复盘（为什么出现？如何解决？如何避免？）

## 📖 详细说明

### 概念解释

达利欧认为，大多数管理者忙于"操作机器"（解决具体问题、扑灭一场又一场的火），而忽视了"设计和改进机器"（优化系统）。优秀的管理者应该像工程师一样，把大部分时间花在优化系统上。

机器的进化循环：发现问题（问题日志）→ 诊断根因（5 个为什么）→ 改进机器（改流程/换齿轮）→ 再运行 → 新问题 → 再循环。这个循环与"痛苦+反思=进步"同构——**机器版的原则工厂**。

与"系统结构决定行为"法则完全同构：行为是结构的产物，改行为必须改结构。

### 实际应用

1. **故障三问**：重复出现的问题=故障，问根因/问部件设计/问"改流程还是换齿轮"
2. **时间分配审计**：救火 vs 优化的时间比，目标向优化倾斜（≥4:6）
3. **原则先行**：先定原则框架，框架内授权各级自主决策
4. **单人版**：个人知识管理 = 单人公司的机器化运营——诊断脚本=体检仪，复盘=问题日志，词条库=原则库

## 💡 个人理解

"不怪人，怪设计"是最解放也最扎心的一句话——它把"我又一次做错了"的自我审判，转换成"我的系统哪里漏了风"的工程问题。对我最直接的映射是知识库运营：断链、标签回流、复盘缺口，全都不是"我懒/我错"，而是机器的某个部件（流程/触发器/提醒）设计有缺陷，应该进问题日志、改设计，而不是写检讨。
